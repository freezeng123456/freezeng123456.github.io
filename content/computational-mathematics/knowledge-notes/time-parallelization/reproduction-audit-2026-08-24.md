本页审计 [ActaPinT-Python](https://github.com/freezeng123456/ActaPinT-Python) 的提交
[`9bf1293`](https://github.com/freezeng123456/ActaPinT-Python/commit/9bf12930a5fbd0403abf8a436c511a90de4025fd)，对应论文 M. J. Gander、S.-L. Wu 与 T. Zhou，_Time Parallelization for Hyperbolic and Parabolic Problems_，以及固定在上游提交 `68431b7` 的 24 份 MATLAB 脚本。审计把“有入口”“能够运行”“与论文数值吻合”和“具备并行性能证据”分开判断。

> [!summary] 结论
> 项目已经为论文 45 张编号图全部提供数值生成器或计算式重绘，并为 3 张表中的 2 张提供本地计算；24 份上游 MATLAB 脚本也都已经移植。因此它的**实现覆盖接近全文完整**。但不能无条件写成“论文所有实验均已复现”：Figure 3.14 在 $\nu=0.02$ 时的 nearest-Kronecker 两条加速曲线仍未匹配，Table 4.1 是引用自另一套三维并行实现的 262,144 核历史结果，当前仓库只能转录；此外，当前未锁定依赖的干净安装有两个数值容差测试失败。

机器可读审计记录见 [[assets/pint/data/full_reproduction_audit_20260824.json|full_reproduction_audit_20260824.json]]。

## 1. 审计口径

本文使用四级证据：

1. **入口覆盖**：图或表在命令行注册表中有独立入口；
2. **产物覆盖**：入口生成参数/指标 JSON 以及 SVG、PNG 或表格产物；
3. **论文吻合**：输出与论文印刷值、数字化标记或像素统计比较；
4. **性能复现**：除数值正确性外，还报告硬件、精度、墙钟与基线。

“画出了相似曲线”只达到第二级。Table 4.1 的原始数据即使被网页收录，也不等于第四级性能实验已由本项目重跑。

## 3. 分章数值证据

### Chapter 2：模型问题

Figures 2.1–2.4 的热方程、对流扩散、Burgers 与波动方程共 24 个面板全部生成。项目不是只做目测，而是把论文 PDF 中的面板校准后进行像素统计：总体中位平滑相关系数为 $0.996$，总体中位十分位错配率为 $0.0026$。Figure 2.3 需要用 $(u^2)_x$ 而不是正文与上游脚本同时写出的 $\frac12(u^2)_x$ 才能匹配激波位置；这是对论文/脚本不一致的诊断，不应悄悄隐藏。

### Chapter 3：对双曲问题有效的方法

SWR、UTP、PIDC/RIDC、ParaExp、ParaDiag I/BVM/NKA 与 ParaDiag II 均有独立入口。代表性量化结果包括：

| 结果                                                      |                                                                    复现值 |
| --------------------------------------------------------- | ------------------------------------------------------------------------: |
| Figure 3.15，热方程 GMRES                                 |                                                                      2 次 |
| Figure 3.15，ADE，$\nu=10^{-3}$                           |                                                                      3 次 |
| Figure 3.15，ADE，$\nu=10^{-6}$                           |                                                                     13 次 |
| 全文 `section3` 入口，Figure 3.15 波动方程 GMRES callback |                                   共 115 次；第 103 次首次低于 $10^{-11}$ |
| 早期 `paper_validation` 入口，同一波动算例                | 第 89 次低于预条件残差 $10^{-11}$；第 103 次满足其 SciPy 真实残差停止条件 |

Figure 3.1 的全部 OSWR 迭代计数、Table 3.1 的 12 个条件数和 Figure 3.15 的主要谱端点也都进入测试。Table 3.2 的顺序 Jacobian 求解列能够精确匹配。

### Chapter 4：为抛物问题设计的方法

Parareal、PFASST、MGRiT、两种对角化 Parareal 与 STMG 的所有编号图均有入口。关键结果为：

| 结果                                                     | 复现值                                           |
| -------------------------------------------------------- | ------------------------------------------------ |
| 全文 `section4` 入口，Figure 4.5 ADE 达到 $10^{-10}$     | 14 / 24 / 35 次                                  |
| 全文 `section4` 入口，Figure 4.5 Burgers 达到 $10^{-10}$ | 14 / 24 / 36 次；使用匹配论文面板的 $(u^2)_x$    |
| 早期 GPU `paper_validation`，Figure 4.5 Burgers          | 14 / 21 / 25 次；使用上游脚本的 $\frac12(u^2)_x$ |
| Figure 4.9，$\nu=0.002$ 的长期因子                       | Parareal 1.421082；MGRiT 1.281200                |
| Figure 4.19，最优采样阻尼                                | Heat 0.500；ADE ($\nu=0.01$) 0.372               |

Figure 4.10 从论文数字化得到的 124 个误差标记整体在 6% 内匹配。论文 Figure 4.9 把 $\nu=0.01$ 的 Parareal 最大因子印成 0.9986，而公式与上游稳定函数给出约 1.0501；项目保留两者并把它列为来源冲突。

这也揭示了项目内两条验证路径不能混用：较早的 `paper_validation` 是 GPU 优化前的代表性子套件；后来的 `section3`/`section4` 才是全文入口。它们在波动 GMRES 的停止/回调口径，以及 Figure 4.5 Burgers 的通量系数上不同。README 与旧知识库曾直接并列这些计数，本审计改为始终注明入口和通量。

## 5. 当前工程可重复性

2026-08-24 在一个全新环境中按 `pyproject.toml` 的开放依赖范围安装，得到 Python 3.12.4、NumPy 2.5.2、SciPy 1.18.1 与 Matplotlib 3.11.1。测试收集 104 项：101 通过、1 个 CUDA 用例因本机无 GPU 跳过、2 项失败。

| 失败测试                         |                                              观测值 | 判断                                                                                   |
| -------------------------------- | --------------------------------------------------: | -------------------------------------------------------------------------------------- |
| Figure 3.10 固定网格比的末端标记 | 0.217770；论文数字化标记约 0.18，原测试相对容差 20% | 超出上界约 0.00177，属于脆弱的读图/版本容差                                            |
| 波动系统的纯虚谱                 |         最大伪实部 $3.24\times10^{-7}$；谱半径约 40 | 相对泄漏约 $8\times10^{-9}$，解析结构未改变，但绝对阈值 $10^{-8}$ 对新版特征值算法过严 |

最新公开 [GitHub Actions 运行](https://github.com/freezeng123456/ActaPinT-Python/actions/runs/30839901657) 同样失败在 Python 3.12 作业。项目只声明 `numpy>=1.26`、`scipy>=1.11` 等下界，没有锁文件或上界；因此历史环境能通过不等于未来的干净安装仍会通过。建议固定一份已验证锁文件，并把解析性质测试改为相对尺度，把数字化标记的容差与读图误差分开。

在同一台机器上改用历史正式记录的 NumPy 2.4.6 与 SciPy 1.17.1 后，Figure 3.10 的容差测试恢复通过，而纯虚谱的绝对阈值仍在 macOS arm64 的稠密特征值计算中失败。这进一步区分了两个问题：前者主要是依赖版本漂移，后者还需要与平台无关的尺度化断言。

同一开放依赖环境下，四个正式分组仍全部运行成功：

| 分组         | 本地计算项 |                            墙钟 |
| ------------ | ---------: | ------------------------------: |
| `schematics` |          6 |                         16.70 s |
| `section2`   |          4 |                         38.13 s |
| `section3`   |         17 |                        784.58 s |
| `section4`   |         20 |                        629.08 s |
| **合计**     |     **47** | **1468.49 s（24 分 28.49 秒）** |

运行生成 47 份 SVG、47 份 PNG 和 48 份 JSON（多出的一份是 Chapter 2 汇总），约 30 MiB。Chapter 2 与已提交指标的最大绝对数值差为 $4.17\times10^{-11}$；Figure 3.1 计数和 Table 3.2 顺序列逐项一致；Figure 4.9 因子最大绝对差约 $8.2\times10^{-13}$。Chapter 3 的发散尾部与舍入放大量不适合用跨 JSON 的单一最大差概括，项目原报告也将这些量排除在稳定引用指标之外。

## 6. T4 GPU 证据的正确边界

现有 2026-07-31 Tesla T4 双精度记录验证的是混合 CPU/GPU 后端：40 个相互独立的 Burgers 细传播被批量放到 GPU，因果粗传播与其他论文实验仍留在 CPU。

| T4 双精度测试                 |      CPU |     GPU | 加速比 |
| ----------------------------- | -------: | ------: | -----: |
| 40 个 Burgers 细传播，32 子步 |  2.893 s | 0.246 s | 11.76× |
| 组合论文验证套件              | 263.57 s | 67.92 s |  3.88× |

单批 CPU/GPU 最大绝对差为 $2.33\times10^{-15}$，早期 `paper_validation` 内的 Figure 4.5 停止迭代保持不变。这组 GPU 记录使用上游脚本的 $\frac12(u^2)_x$，不应与全文 `section4` 为匹配论文面板而使用 $(u^2)_x$ 得到的 14/24/36 次混为一谈。它证明了单 T4 上特定热点的数值一致性和端到端收益，不证明多 GPU、MPI 或 Table 4.1 的强弱扩展。

## 7. 最终判断

- 若问题是“论文每个章节是否都有代码入口”，答案是**有**：Chapter 1/5 无数值实验，Chapters 2–4 的所有编号图均有本地入口或计算式重绘。
- 若问题是“论文所有实验数值是否都被无例外复现”，答案是**没有**：Figure 3.14 的两条 NKA 曲线和 Table 4.1 是明确缺口，另有三组有界差异。
- 若问题是“当前任意干净环境是否一键稳定通过”，答案仍是**没有**：最新 CI 与本次开放依赖安装均有两个数值容差问题，需锁定依赖并稳健化测试。
- 若问题是“GPU 是否验证了全文算法的并行扩展”，答案是**没有**：T4 证据只覆盖单 GPU 混合后端的 Burgers 批处理热点。

因此最准确的项目表述是：**全文实现覆盖已经基本完成，绝大多数图表获得了定量复现；项目仍保留一个局部曲线缺口、一个外部超算表格缺口，以及当前依赖漂移导致的工程可重复性问题。**
